# 事故紀錄

**未來任務需要知道的坑。** 只記「下一個碰到這塊的人，不知道這件事會不會出事」的問題 ——
判準、格式、狀態語意、歸檔規則全部見 `record` skill，本檔不重述。

開工前用**要改的檔名**和**功能名**各 grep 一次：

```bash
grep -n "<檔名>" docs/KNOWN-ISSUES.md
```

ID 單一系列 `K-<n>`，遞增，**永不重用**。執行者自己的失誤也記。

### K-1 用術語但沒確認它的既定含義，變成把英文詞當縮寫用

- **影響範圍**：`.claude/skills/`（全部 skill 文件）
- **狀態**：已修（無守備）
- **症狀**：`code` skill 用 `scope guard` 當標題指涉「範圍控制」、用 `clean code`
  指涉「收尾 checklist」。兩者都是既有術語，但既定含義完全是別的東西
  （前者是 C++ 的 RAII idiom，離開作用域執行資源清理；後者是命名／函式大小／
  SRP／註解的程式碼品質原則）
- **根因**：把「用術語」執行成「換上英文詞讓文字變短」，跳過了「這個詞原本指什麼」
  這一步。表面症狀是文字變精簡了，實際上是**指向錯誤概念的精簡**，比冗長更糟 ——
  讀者會照著術語的既定含義去理解，而那不是作者的意思
- **判準**：下筆前確認兩件事 ——
  ① **這個詞的既定含義是什麼**（查，不要憑印象）
  ② **它替掉了哪一段解釋**（替不掉就直接寫中文，更誠實）。
  自檢訊號：**用了術語卻還要補幾條說明**，代表要嘛術語多餘、要嘛用錯了
- **關聯**：與 K-2 同屬「規範文件自己的失效形態」
- **日期**：2026-08-11

### K-3 去實例化時，把「方法」與「限定條件」跟實例一起刪掉

- **影響範圍**：`.claude/skills/`（全部 skill 文件）、任何做「移除範例、保持中性」的文件改寫
- **狀態**：已修（無守備）
- **症狀**：一次收斂中出現三種形態 ——
  ① `code` 的 mutation 指令變成可複製的 code block，但**沒寫前置條件**
  （改動必須已 commit）。照 `CLAUDE.md` 的 L1 流程（改完就 mutation，工作區未 commit）
  字面執行，第一行覆蓋工作區、還原指令只還原到 HEAD，**正在寫的東西靜默消失**
  ② `deliver` 說「做法見 `verify` §5」，但探測指令在**兩份**都被刪 —— 方法在整個 repo 不存在
  ③ `record` 刪掉「腳本只查測試存在、不執行測試」的限定，只留指向決議編號，
  而該決議的表述讀起來像「保證測試為綠」→ 文件開始 over-claim
- **根因**：把「移除實例」執行成「移除所有具體內容」。**可執行的指令、前置條件、
  能力邊界都不是實例** —— 它們是規範的可執行部分，刪掉會產生
  **看起來完整、照做會出事**的文件。而且這種缺陷在 grep 式檢查下完全隱形
- **判準**：去實例化前先把段落內容分三類 ——
  **實例**（某次發生過什麼，可刪）／**方法**（怎麼做，要留）／**限定條件**
  （前置、邊界、例外，**最該留**）。
  自檢：刪完後問「照這段字面執行，會不會出事？會不會找不到怎麼做？」
- **關聯**：K-1、K-2 同屬「規範文件自己的失效形態」；與 K-4 同一次 code review 發現
- **日期**：2026-08-11

### K-4 用 grep 關鍵字做「內容無損」驗收，抓不到刪減造成的缺陷

- **影響範圍**：文件改寫的驗收流程、`docs/tasks/` 的驗證步驟
- **狀態**：已修（無守備）
- **症狀**：一次大幅改寫連續三輪自我驗收都是綠燈（判準關鍵字全部命中），
  但獨立 review 隨即找到 11 個問題，其中 1 個高危、6 個 medium
- **根因**：grep 只能驗證**我列進清單的東西還在**，結構上抓不到三類缺陷：
  ① 被刪掉的限定條件（不在清單裡，因為列清單的人就是刪的人）
  ② 語意矛盾（關鍵字都在，但湊起來自相矛盾）
  ③ 跨檔的方法遺失（A 指向 B，B 也被刪了 —— 兩邊各自看都正常）
- **判準**：宣稱「內容無損」時，**grep 只能當輔助**。真正的做法是
  **取回舊版全文，與新版逐段對讀**（`git show <base>:<檔案>`）。
  更可靠的是**換一個人（或另一個 agent）讀** —— 刪的人與驗的人是同一個時，
  他不會去找自己認為不重要而刪掉的東西
- **關聯**：K-3
- **日期**：2026-08-11

### K-2 checklist 內容是正文的複述，零新資訊

- **影響範圍**：`.claude/skills/`（全部 skill 文件）
- **狀態**：已修（無守備）
- **症狀**：`code` skill 末尾的收尾 checklist 三條，逐條對回去分別是正文
  §2／§3／§5 的重述
- **根因**：沿用其他 skill「末尾有 checklist」的慣例，但沒問「**這個 checklist
  有沒有增值**」。慣例被當成理由使用
- **判準**：checklist 只在**跨小節**或**補充正文未講的內容**時保留；
  純複述一律刪 —— 重複的兩份一定會漂移（`record` skill 已明文），
  而規範文件漂移的代價是讀者不知道該信哪一份
- **關聯**：K-1
- **日期**：2026-08-11

### K-5 機制存在但預設路徑難用，於是「沒啟用」被誤判成「環境故障」

- **影響範圍**：`sandbox.sh`、`docker-compose.claude.network.yml`、
  `scripts/entrypoint.sh`；以及任何「留了選用機制但沒做成預設路徑」的設計
- **狀態**：已修
- **守備**：`scripts/entrypoint.sh`::`print_network_summary` —— 兩種狀態都會印出一行，
  「沒接上網路」不再是無聲的。`sandbox.sh` 則讓接上網路變成預設路徑
- **症狀**：一個 session 在 sandbox 內判定「no network/docker access to the live
  infra」，據此把交接文件上多項工作標為 `literally not executable from here`，
  並要求使用者改變工作方向。實際上專案服務全部正常運行中 —— 只是 sandbox 啟動時
  漏了 network overlay。實測三種症狀同時出現：服務名 `curl` exit 6（解析不到）、
  直接打 IP exit 28（逾時，封包被 `OUTPUT DROP`）、`localhost:<host port>` exit 7
- **根因**：兩層。表層是要正確啟動得同時記住兩個 `-f`、`WORKSPACE_DIR`、
  `APP_NETWORK_NAME` 四件事，且舊版 README 還要求專案改自己的 compose 把網路
  改名 —— 選用機制的門檻高到實務上等於預設關閉。深層是**這個失敗沒有任何輸出**：
  沒有錯誤、沒有警告，只有「什麼都連不到」。而「什麼都連不到」最自然的解釋
  就是環境壞了，不是「我少帶了一個參數」
- **判準**：
  ① 判定「環境沒有 X 能力」之前，先確認**自己處在哪個環境切面** ——
  容器內先看 `ip -4 -o addr show` 的網段、對照目標服務的網段，再下結論
  ② 設計面：**選用機制若沒有預設路徑，就要有失敗時的明確輸出**。
  兩者都缺時，使用者會用「整個壞了」來解釋，而那個解釋會擴散成錯誤的工作決策
  ③ 自檢訊號：**結論是「這件事做不到」而不是「這件事失敗了」** ——
  前者是能力判斷，需要比後者更強的證據
- **關聯**：與 K-1～K-4 不同類 —— 那四則是規範文件自己的失效形態，本則是執行環境的
- **日期**：2026-08-12
