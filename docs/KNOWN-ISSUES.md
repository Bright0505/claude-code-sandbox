### K-1 用術語但沒確認它的既定含義，變成把英文詞當縮寫用

- **影響範圍**：`.claude/skills/`（全部 skill 文件）
- **狀態**：已修（無守備）
- **症狀**：`code` skill 用 `scope guard` 當標題指涉「範圍控制」、用 `clean code`
  指涉「收尾 checklist」。兩者都是既有術語，但既定含義完全是別的東西
  （前者是 C++ 的 RAII idiom，離開作用域執行資源清理；後者是命名／函式大小／
  SRP／註解的程式碼品質原則）
- **根因**：把「用術語」執行成「換上英文詞讓文字變短」，跳過了「這個詞原本指什麼」
  這一步。表面症狀是文字變精簡了，實際上是**指向錯誤概念的精簡**，比冗長更糟 ——
  讀者會照著術語的既定含義去理解，而那不是作者的意思
- **判準**：下筆前確認兩件事 ——
  ① **這個詞的既定含義是什麼**（查，不要憑印象）
  ② **它替掉了哪一段解釋**（替不掉就直接寫中文，更誠實）。
  自檢訊號：**用了術語卻還要補幾條說明**，代表要嘛術語多餘、要嘛用錯了
- **關聯**：與 K-2 同屬「規範文件自己的失效形態」
- **日期**：2026-08-11

### K-2 checklist 內容是正文的複述，零新資訊

- **影響範圍**：`.claude/skills/`（全部 skill 文件）
- **狀態**：已修（無守備）
- **症狀**：`code` skill 末尾的收尾 checklist 三條，逐條對回去分別是正文
  §2／§3／§5 的重述
- **根因**：沿用其他 skill「末尾有 checklist」的慣例，但沒問「**這個 checklist
  有沒有增值**」。慣例被當成理由使用
- **判準**：checklist 只在**跨小節**或**補充正文未講的內容**時保留；
  純複述一律刪 —— 重複的兩份一定會漂移（`record` skill 已明文），
  而規範文件漂移的代價是讀者不知道該信哪一份
- **關聯**：K-1
- **日期**：2026-08-11
