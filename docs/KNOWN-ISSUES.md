### K-5 機制存在但預設路徑難用，於是「沒啟用」被誤判成「環境故障」

- **影響範圍**：`sandbox.sh`、`docker-compose.claude.network.yml`、
  `scripts/entrypoint.sh`；以及任何「留了選用機制但沒做成預設路徑」的設計
- **狀態**：已修
- **守備**：`scripts/entrypoint.sh`::`print_network_summary` —— 兩種狀態都會印出一行，
  「沒接上網路」不再是無聲的。`sandbox.sh` 則讓接上網路變成預設路徑
- **症狀**：一個 session 在 sandbox 內判定「no network/docker access to the live
  infra」，據此把交接文件上多項工作標為 `literally not executable from here`，
  並要求使用者改變工作方向。實際上專案服務全部正常運行中 —— 只是 sandbox 啟動時
  漏了 network overlay。實測三種症狀同時出現：服務名 `curl` exit 6（解析不到）、
  直接打 IP exit 28（逾時，封包被 `OUTPUT DROP`）、`localhost:<host port>` exit 7
- **根因**：兩層。表層是要正確啟動得同時記住兩個 `-f`、`WORKSPACE_DIR`、
  `APP_NETWORK_NAME` 四件事，且舊版 README 還要求專案改自己的 compose 把網路
  改名 —— 選用機制的門檻高到實務上等於預設關閉。深層是**這個失敗沒有任何輸出**：
  沒有錯誤、沒有警告，只有「什麼都連不到」。而「什麼都連不到」最自然的解釋
  就是環境壞了，不是「我少帶了一個參數」
- **判準**：
  ① 判定「環境沒有 X 能力」之前，先確認**自己處在哪個環境切面** ——
  容器內先看 `ip -4 -o addr show` 的網段、對照目標服務的網段，再下結論
  ② 設計面：**選用機制若沒有預設路徑，就要有失敗時的明確輸出**。
  兩者都缺時，使用者會用「整個壞了」來解釋，而那個解釋會擴散成錯誤的工作決策
  ③ 自檢訊號：**結論是「這件事做不到」而不是「這件事失敗了」** ——
  前者是能力判斷，需要比後者更強的證據
- **關聯**：無同形態條目。本則是**執行環境**的失效（不是規範文件自己的失效形態）
- **日期**：2026-08-12

### K-6 測試是綠的，但把它要守的那行程式碼拿掉之後還是綠

- **影響範圍**：`scripts/test-git-auth.sh`、`scripts/test-init-firewall.sh`；
  以及任何「用 grep 判斷某項在清單裡」或「用 `chmod` 造權限情境」的測試
- **狀態**：已修（守備見下）
- **守備**：`scripts/test-init-firewall.sh`::`設了自架站台時 gitlab.com 仍在白名單`、
  `scripts/test-git-auth.sh`::`HOME 不存在 → exit 非 0`
  （mutation 驗證：① 刪掉 `init-firewall.sh` 靜態白名單裡 `gitlab.com` 那一行
  ② 把 `[ ! -w "${HOME:-/nonexistent}" ]` 改成 `if false` —— 兩者都轉紅）
- **症狀**：同一輪內出現三種形態，全部是「測試通過，但通過的原因不是被測的那段程式碼」——
  ① 斷言被**預設值**滿足：測「`gitlab.com` 在白名單」，但 `forge_gitlab_host` 預設就回
  `gitlab.com`，所以把靜態白名單那行整行刪掉，15 條測試仍全綠
  ② `grep -w` 的字界把子字串算成命中：`grep -w github.com` 在 `api.github.com` 上也命中，
  於是「`github.com` 在白名單」這條斷言恆真
  ③ 以 **root** 執行時 `chmod 500` 不生效（root 繞過權限檢查），`[ -w <dir> ]` 仍為真，
  「HOME 不可寫要大聲失敗」這條假綠
- **根因**：三者共通 —— **斷言的通過路徑不只一條**，而測試只證明了「有一條路徑讓它通過」，
  沒有證明「被測的那條有效」。① 是 derived 值補上了被刪的靜態值；② 是比對方式比意圖寬；
  ③ 是執行身分讓前置條件不成立。三種都不會有任何錯誤輸出
- **判準**：
  ① 每寫完一條斷言就問「**把我要守的那行刪掉，這條會紅嗎**」，不確定就真的刪一次跑一次
  ② 清單成員用整項精確比對（`grep -qx`／`in_list`），不要用 `-w`
  ③ 權限／擁有者情境要在**非 root** 身分下驗（`setpriv --reuid=…`），
  root 下這類測試沒有鑑別力；改用「路徑不存在」這種對任何身分都成立的前置條件
- **關聯**：無同形態條目。形態名稱為**「驗收方法本身無法偵測缺陷」** ——
  同形態的另一種面貌（用 grep 關鍵字做「內容無損」驗收）發生在上游研發階段，
  紀錄未隨產品出貨；再遇到時用這個形態名稱建立關聯
- **日期**：2026-08-13
