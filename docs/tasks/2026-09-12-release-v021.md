### ⚠️ 更正（2026-09-17）：上一項把「已修的缺陷」引用成「現存的限制」

「整套 suite 是 Linux-only（見 v0.1.0 的 CHANGELOG），這台 macOS host 跑不完」
—— **引用方向是反的**。`v0.1.0` 的 CHANGELOG 把那件事列在「**修正**」欄位：

> **修正** —— `scripts/test-*.sh` 在 macOS host（bash 3.2）跑不完，兩個獨立的
> Linux-only 依賴。README 補「腳本的執行層」：**不需要 docker ≠ 不需要 Linux**

也就是那份 CHANGELOG 記的是**這個缺陷已經被修掉**，不是它還在。commit `9ee835c`
（2026-08-24，隨 `v0.1.0` 出貨）逐條寫出兩個根因的修法：`test-init-firewall.sh`
的全形括號讓 bash 3.2 吃進變數名 → 改 `"${d}（…）"`；`init-firewall.sh` 依賴
`/sys/class/net` 與 GNU `find -printf` → stub 補上 `find`。`README.md`
「腳本的執行層」也把這兩支歸在 **host（測試）** 層、註明 bash 3.2 相容。

**三個獨立載體一致，本檔是唯一的異常值**，而且它引用的正是那份說相反話的 CHANGELOG。

**這不是推翻當時的決定**（那一輪只改註解，不跑整套 suite 本來就站得住），
是修正一句**錯誤的引用**——它把「可以跑但這次不需要跑」寫成了「跑不了」，
兩者對下一個人的意義完全不同。原文保留（禁令 8）。

**尚未實跑**：本次在 Linux 容器內跑過三支套件全綠（43／15／52），
**沒有在 macOS host 上跑過** —— 若你的 Mac 上仍然失敗，那是一個**新的**事故，
不是這則更正寫錯。

**形態**：引用一份有狀態欄位的紀錄時，只取條目的**內容**、沒取它所在的**欄位**
（「修正」vs「已知未驗」），語意會整個反轉。判準見
`docs/tasks/2026-09-17-docs-staleness-audit.md` 的問題紀錄。

## 稽核結果（`release` skill §3／§5）

### ① §3 引用審計：一個跨了三個版本的死指標

`scripts/test-git-auth.sh:6` 指向 `docs/tasks/2026-08-13-git-forge-token-auth.md`，
而那份任務檔在 `2d24251`（移除上游研發紀錄）就從 `dev` 拿掉了。
`scripts/` 是產品檔 → **v0.1.0 起每一版出貨的都帶著這個指不到東西的指標**。

為什麼前兩版的稽核沒抓到：v0.2.0 那次把範圍從「只掃 `.md`」擴到產品檔清單
（`K-5` 的教訓），但 pattern 只針對條目 ID `K-<n>`／`D<n>` 與 `docs/` 三個檔名，
**沒有涵蓋 `docs/tasks/<具體檔名>`**。這次補掃 `docs/tasks/[0-9]{4}-...` 才看到。

處理：不是把指標刪掉了事。被指向的「這套測不到什麼」在產品裡沒有別的載體
（§2：移除引用前先確認判準有載體），所以把那三項搬進腳本自己的檔頭；
自架 GitLab 那一項 `README.md:102-103` 已經有了，只留一行指過去。

### ② §5 洩漏面掃描：零命中，但零命中不算證據

11 條 pattern 跑一次出命中表。有命中的都能歸類、都不是洩漏：
`example.com` 佔位、`ghp_xxxxxxxx`／`glpat-xxxxxxxx` 佔位、
`172.31.x` 是 `test-init-firewall.sh` 裡假造的 `ip addr` 輸出、
`Bright0505/claude-code-sandbox` 是上游自己的位址（§7 要求取回指針要帶）。

第二角度（§5 要求）：把 `release/skeleton/` 三份整份讀過。零條目、
沒有上游專案名／網段／主機路徑。

### ③ 一次性設定

`gh repo view`：`isTemplate=true`、default branch `main`。兩項都對。
