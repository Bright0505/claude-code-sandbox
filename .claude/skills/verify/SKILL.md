# 驗證

`CLAUDE.md` 已定義相關鐵則。本 skill 是「宣稱驗過了」這件事的具體做法。

---

## 1. 下結論前：一手來源優於二手

任何人（包含使用者）的陳述都是**意圖層**的資訊，不是事實。
寫進結論前先問：**這是我親眼看到的輸出，還是有人告訴我的？**

判準不是「不信任」，是**結論要自己能重現**。陳述可以當線索去查，不能直接當結論用；
查證成本通常遠低於查錯之後的收拾成本。

而且查證常常**多帶回一點東西** —— 為了確認 A 而跑的指令，
往往順便解掉了另一個以為做不到的問題。單純採信不會有這個副產品。

---

## 2. 寫測試時：沒紅過不算測試

```
1. baseline    先跑現有測試並記下結果 —— 沒有 baseline，全過也證明不了「原本能做的還能做」
2. mutation    故意弄壞被測目標，確認測試真的轉紅
3. revert      還原
4. green       確認轉綠
```

第 2 步不可跳過。跳過等於沒驗證測試本身有沒有**斷言錯位置**、
有沒有寫成**恆真式**。過程中抓到的紅燈不是雜訊，那正是這個流程要抓的東西。

改既有程式碼時 mutant 怎麼取，見 `code` skill。

---

## 3. 改動之後：regression 要整套跑

- 有測試套件 → **改完整套重跑**，不是只跑新加的部分。
  只跑新測試只能證明新東西沒錯，證明不了既有行為沒被破壞
- 沒有測試套件，或改的是文件／規範 → 退化成「**有沒有可觀察的行為改變**」，
  對現有真實資料重跑一次檢查工具，確認輸出乾淨且沒有新警告

---

## 4. 工具回報時：避免 over-claiming

一個檢查只能宣稱它**真的檢查過**的東西。做法是區分兩種輸出語意：

| 類型 | 語意 | 是否擋流程 |
|---|---|---|
| error | 事實性、可判定 | 擋 |
| warning（需人判斷）| 只攤出一個事實，不代表任何結論 | 不擋 |

兩條配套：

- **輸出要講清楚「沒檢查什麼」**，不是只講檢查了什麼
- **命名不可暗示做不到的宣稱** —— 名字裡出現語意層的詞（「驗證正確性」「確保一致」），
  綠燈就會被讀成那個意思

---

## 5. 承諾動作前：先探測環境能力

承諾一個動作（push、開 PR、跑某個指令）之前，先驗證環境**真的做得到**，
不是假設「應該可以」再去試。

```bash
gh auth status                              # 有沒有已認證的 CLI
which ssh                                   # 有沒有 SSH client
env | grep -iE "GH_TOKEN|GITHUB_TOKEN"      # 有沒有 token
```

三者都沒有，就是真的做不到 —— 直接說清楚環境缺什麼，附上實際跑的指令與輸出。

**「做不到」跟「沒試」是兩個不同的結論** —— 前者要有查證過程撐著，後者只是還沒查。

反向同樣成立：**不要因為「以前不行」就假設現在也不行**。
先探測再說，那經常會發現替代路徑（見 `traps` §1）。

---

## 6. 要跑一連串檢查時：合成一次執行，不要逐次互動

驗證的成本不在輸出的資料量，在**往返次數** —— 每一次往返都要重新帶進當時的
全部脈絡，而脈絡只會單向變大。所以同一批檢查「分十次做」會比「寫成一支腳本
跑完」貴數倍，而且貴的部分完全沒有換到任何額外資訊。

- **合批**：同一輪要查的事實寫成一支腳本／一條指令，一次跑完
- **只輸出摘要** —— 判定結果與關鍵數字，不是原始輸出全文。要用的欄位就取那幾個，
  加上限；**整份讀進來的東西，之後每一次往返都要再付一次**
- **迴圈化**：N 個 mutant 用迴圈跑，一次輸出「哪一條轉紅」的對照表，
  不要一個一個手動改、跑、還原

⚠️ **限定條件：互相依賴的步驟不能合批。** 後一步要看前一步的輸出才能決定怎麼下時，
合批就變成猜。這一節只適用於**彼此獨立、而且都一定要做**的檢查。

---

## 7. 決定驗到多細時：先問這個結果會不會改變決策

會改變接下來動作的檢查才做。跑完只是讓某句話「聽起來更有底氣」的，不要跑 ——
把「未實測」寫進交付物，比多跑一輪便宜，而且誠實度相同。

mutation 的數量按 effort sizing 走。上限管的是**額外的 mutation 掃描** ——
§2 的「每一條新測試都要親眼看它紅過一次」**任何強度都要做，不計入上限**：

| 強度 | 額外的 mutation 掃描 |
|---|---|
| L0／L1 | 不做 —— §2 那一次就夠 |
| L2 以上 | 挑**守住核心行為**的那幾條斷言，各弄壞一次；一輪上限約四個 |

**兩個例外，上限在這兩種情況下不適用**：

1. **已經抓到一個假綠** —— 它證明的不是「這條寫壞了」，而是這一批斷言的寫法
   有系統性問題。同一種寫法的其他斷言全部要重驗
2. **§3 的 regression 整套重跑** —— 那是一次執行，不是 N 次往返，不受上限限制

⚠️ **上限管的是重複佐證與例行 mutation 的數量，不是 `CLAUDE.md` 鐵則 1-4 的下限。**
宣稱驗過的事一定要有一手證據；省掉的只能是「同一件事的第二份佐證」。
